# Architecture

HOW_CODE_WORKS uses a Next.js App Router frontend with a small server boundary for execution. The interactive workspace is a client component because Monaco, draft switching, stdin editing, and execution state require browser state.

`app/page.tsx` owns the workspace composition. Language drafts are kept independently in one state object, so switching languages does not discard edits.

`app/api/execute/route.ts` is the only browser-facing execution boundary. It validates JSON with Zod, applies source and stdin limits, invokes the provider adapter, and returns normalized JSON. `lib/compiler/types.ts` contains provider-independent contracts; `lib/compiler/judge0-provider.ts` is the Judge0-specific adapter and maps C, C++, and Java to verified Judge0 language IDs.

This boundary keeps provider tokens server-side and makes it possible to add another execution service without changing the editor UI. Intermediate artifacts are not generated by the current route.
