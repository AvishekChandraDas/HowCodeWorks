# HOW_CODE_WORKS

HOW_CODE_WORKS is an interactive Compiler Construction learning workspace. It combines a Monaco code editor, standard input, execution diagnostics, and real sandboxed execution for C, C++, and Java.

## Getting started

```bash
npm install
cp .env.example .env.local
npm run dev
```

The editor works without credentials. Local development defaults to the public Judge0 CE endpoint so the Run action works immediately. For coursework or production use, configure your own compatible Judge0 CE deployment in `.env.local`; credentials stay server-side and are only read by the API route.

## Commands

`npm run dev` starts development, `npm run lint` checks the codebase, and `npm run build` creates the production build.

## Architecture

- `app/page.tsx` owns the interactive workspace UI and per-language drafts.
- `app/api/execute/route.ts` validates requests and keeps provider access server-side.
- `lib/compiler/types.ts` contains provider-independent execution models.
- `lib/compiler/judge0-provider.ts` normalizes Judge0 results into the application model.
- `lib/compiler/validation.ts` enforces source and input limits with Zod.

The application displays provider responses directly and never fabricates compiler output or execution metrics.

## Limitations

The current release uses Judge0 for final execution. Intermediate C/C++ and Java artifacts are not generated by the Next.js process. Production deployments should add a distributed rate limiter and use a hardened Judge0 deployment with its own sandbox controls.
